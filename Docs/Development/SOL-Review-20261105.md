## 먼저 다룰 버그4개

### CAM-LOCK

현재 `VoxArena.Camera.cs`의 락온 분기는 적 방향으로 yaw를 보간하고 pitch를 기본값으로 되돌린다. `TryAcquireTargetLock`은 거리와 기체 허용만 검사하며 획득 단계에서 화면 안/LOS 조건을 검사하지 않는다. 유지 단계의 화면/LOS 검사와 순서가 다르다. 이는 재중심화나 반복 획득 문제의 후보이며, 하늘/땅 급회전의 확정 원인은 아니다.

재현안: BASTION/TARANTULA 각각 상대가 뒤/위/아래, 가까이 교차, 벽 뒤, RMB 유지/반복 클릭, 포커스 복귀, 저프레임 상황. 입력 dx/dy, 카메라 yaw/pitch, targetLock 전환 사유, LOS, 타깃 높이를 기록한다. 획득·유지·해제 상태와 카메라 전환을 분리하고 각속도 제한/사용자 시야 의도를 검토한다. WISP 완전 락온 금지와 벽 충돌 검사를 보존한다.

### AIM-ASSIST

현재 발사 순간 최대1도, 후보각1.8도, 뷰포트/LOS/거리 조건 및 이동별 강도 변화가 있다. 이것은 RMB 락온처럼 타깃을 붙들어 두는 시스템이 아니다. 단순히 오래 유지하도록 바꾸면 엄폐물 너머 보정이나 자동추적이 생긴다.

재현안: 조준/사거리/화면 경계 통과, 얇은 엄폐, 정지↔이동↔부스트↔공중, 좌우 무기 총구의 차이. 후보 선택/피드백에는 획득·해제 히스테리시스를 검토하되, 실제 발사 때 LOS와 허용 보정량은 다시 검증한다. 강도를 먼저 키우기보다 어느 조건에서 보정이 빠지는지 가시화한다. 카메라 스냅/발사 후 유도는 추가하지 않는다.

### ANIM-GRIP

현재 무기는 소켓에 붙지만 팔 애니메이션은 주로 이동 gait 기반 회전과 WISP 방패 포즈다. 무기별 그립 목표·팔꿈치 방향·양손 협응은 충분하지 않다.

수정안: Blender 무기/리그에 주손·보조손 그립, 총구, 팔꿈치 방향 기준을 정의하고 무기별 포즈를 섞는다. 필요 시 팔 IK를 사용하되 기존 다리/방패 리그와 분리한다. 라이플/포/검·위아래 조준·횡이동·점프·가드 조합에서 손-그립 오차, 관절 꺾임, 총구-발사 방향을 실제 화면으로 비교한다.

### ANIM-QUAD

현재 사족은 `roundTime*9` 위상에 고정된 작은 lift와 속도비 stride를 사용한다. 진행 거리 기준 보폭/주기와 발 지지 유지가 충분하지 않다. 접지 IK가 있다는 것과 자연스러운 보행은 별개다.

수정안: 실제 이동 거리/방향에 따라 보행 위상을 진행하고, 지지 중 발 고정과 스윙 궤적·보폭·높이·속도·회전 보행을 나눈다. 저속/고속/전후좌우/제자리 회전/경사에서 발 미끄럼·몸통 흔들림과 기존 접지 오차를 확인한다. 새 고속 대시 금지는 현재 Cruise 부스터와 다른 전투 규칙이므로 별도 착수 범위에 포함해야 한다.

## 데이터와 저장의 선행 관계

권장 구조:

1. `PartDefinition`/`WeaponDefinition`: 안정 ID, 데이터 버전, 타입/행동/아이콘 태그, 능력치, 호환 마운트, 모델/리그 연결. 정식 카탈로그와 시험 사본을 분리한다.
2. `RobotBuild`: 이름/여러 줄 설명/파츠·무기 ID/영역별 색/구성만 가진다. 사용자8슬롯은 3예시+5빈칸으로 시작한다.
3. `DeveloperPreset`: 001~010 별도 저장. 수치·카메라·환경의 실험 오버라이드와 참조 기준 버전을 보관한다. 일반 설계도에는 넣지 않는다.
4. `ResolvedRuntimeStats`: 정식 데이터+빌드+승인된 실험값에서 실제 전투 수치를 계산한다. 저장용 데이터와 순간 탄약/열/쿨타임 상태를 섞지 않는다.
5. 일반 저장은 임시파일→검증→교체, 백업/복구, 입력 길이/범위/중복ID 검증을 갖춘다. 삭제·덮어쓰기·미저장 확인은 취소를 기본으로 한다.

현재 프로필은 이름/마운트 문자열과 공격력·간격·탄속·반경·사거리·탄창 정도만 가진다. 무기별 장전은2.5/4초 공통이며 초기 탄약도 정적 Loadout을 참조한다. 용량을 편집하도록 확장할 때 초기화·재장전·HUD를 모두 같은 프로필로 통일해야 한다. 현재 발사 간격/흩어짐이 모든 슬롯에서 오른팔 handling/stability를 참조하는 점도 무기 마운트별 계산으로 정리해야 한다.

현재 부위 루트가 나뉘어 있다고 임의 파츠 교체가 완성된 것은 아니다. 3종 하체의 뼈 구조, 혼합 스킨 호스, 발 IK·접지·피격 반경이 다르므로 공통 소켓/호환표와 리그 어댑터가 선행되어야 한다. 처음에는 호환되는 파츠만 제공하는 편이 안전하다. 색 변경은 공유 머티리얼 원본을 수정하지 않고 빌드별 색 영역으로 처리한다. 아이콘은 행동/능력치 데이터에서 생성하며 임의 장식 아이콘과 실제 기능이 불일치하지 않게 한다.

‘프리셋003 정식 적용’은 명시적 검증/차이 확인/승인 후 정식 데이터 후보를 만드는 단계다. 버튼이 런타임 사본을 정식 기본값이나 main에 몰래 덮어쓰지 않도록 한다.

## 설계도 암호화와 호환

요청서의 인증 암호화·비밀번호 KDF·salt/nonce·버전 정보를 전제로 설계하되, 실제 Unity Windows 런타임에서 API/라이브러리 지원과 배포를 먼저 검증한다. 아직 암호화 구현 가능 검증을 했다고 보고하지 않는다. 자체 암호 알고리즘을 만들지 않는다.

파일은 메시 없이 안정 ID/색/구성만 담는다. 비밀번호·개발자 오버라이드를 저장하지 않으며 메타데이터도 무결성 보호한다. 인증 실패/손상/미래 버전/누락ID/큰 파일/과도한 KDF 설정을 구분해 처리하고, 인증·검증·마이그레이션을 끝내기 전에는 슬롯을 변경하지 않는다. 이전 버전 골든 파일과 잘못된 비밀번호/변조/중단 저장/원본 보존 시험이 필요하다. 암호화는 설계도 비밀성과 무결성을 위한 것이며 치트 방지나 DRM을 대신하지 않는다.

## 전투·환경·성능 위험

- 캐릭터 이동은 현재 사용자 정의 Move/Bounds 해결 경로이므로 반동을 별도 Rigidbody 힘으로 추가하면 끼임·경계 돌파가 생길 수 있다. 기존 이동/충돌 해결에 반동 속도와 상한·회복을 통합한다. 중량 상시 효과, 락온 중 비용, 발사 경직을 따로 계산하고 중복 페널티와 무한 경직을 막는다.
- 공유 코어 에너지와 장비별 열은 분리한다. 순간 출력 부족 시 부스터/무기 중 우선순위, 빈 에너지/과열 복귀 조건을 먼저 정한다. 수소 장비나 잔류 에너지 보조는 새 전투 규칙이며 즉시 자동 구현하지 않는다.
- 환경8요소 모두 설계 대상으로 유지한다: 먼지(시야/센서), 진흙(마찰/제동), 온습도(냉각), 연기·잔해(바람/가시성/경로), 경사·고도(기동), 전자기 간섭(센서/유도), 역광(시각/센서), 결빙(마찰/냉각). 공통 환경 상태와 제한된 상호작용 계수로 연결하고 단계별로 켠다.
- 바람은 허용된 발사체/연기/빗줄기 궤적에 적용하며 단순 명중률 감소로 대신하지 않는다. 물웅덩이는 현재 감속하지 않으므로 진흙/결빙 도입은 기존 규칙 변경이다.
- 환경/AI/전투/VFX의 랜덤 흐름을 분리한다. 시드만 같아도 프레임·입력·카탈로그가 다르면 같은 경기라고 보장할 수 없다. 시드+환경 설정/버전+고정 시뮬레이션 기준과 이벤트 기록을 구분한다.
- 좌우 미러와 후방 화면3개를 매 프레임 본 화면과 같은 해상도로 렌더하면 추가 카메라·그림자 비용이 크다. 낮은 해상도/갱신 빈도, 필요한 때만 활성화, 레이어 제한·별도 그림자 정책을 비교 측정한다. 조종석 미니맵/계기에는 별도 3D 카메라가 필요 없는 항목도 있다.
- 기존 V는 음소거다. 새 V 시점 순환과 충돌하므로 음소거를 다른 키로 옮기고 가이드/설정도 함께 갱신해야 한다. 1인칭은 기본 시점 확정이 아니라 비교 후보로 다룬다. 카메라 흔들림은 실제 조준 레이와 시각 진동을 구분하고 멀미 강도/끄기를 제공한다.
- 미래3v3를 위한 팀 식별 데이터는 고려하되 이번에 온라인/팀전까지 확장하지 않는다. 동색 상대도 외곽/표식 등으로 구별한다.
