# 무기 기본 수치 간소화 — 1차 반영

작업 기준은 `main`의 `Docs/Design/Weapon_Stats_Simplification_v01.md` (기획 커밋 `76f36ad`)이다. 이번 단위는 `work`에서 재장전 시간 통합만 반영했다.

## 변경 내용

- 밸런스 데이터 형식을 6으로 올리고 `reloadTime`을 추가했다.
- 기존 `partialReload`와 `emptyReload` 값은 저장 데이터에서 보존한다. 새 필드가 없는 이전 파일은 두 값 중 긴 값을 `reloadTime`으로 채워 기존 무기의 재장전이 갑자기 빨라지지 않게 한다.
- 편집 화면은 기존 두 필드 대신 `reloadTime` 하나를 보여준다. 발사 후 재장전, 빈 탄창 재장전, 대기 후 자동 재장전, HUD 게이지, 가상 대전 프로필이 같은 시간을 참조한다.
- `idleReload`는 자동 재장전을 시작하기까지의 내부 대기 시간으로 남겼다. 아직 발사 방식·특수 효과·무게·반동은 바꾸지 않았다.
- PD 소유 파일 `Data/Balance/PD-Balance.json`과 백업은 수정하지 않았다.

- 빌드 도구가 `Assets/Scenes/Arena.unity`를 다시 저장했지만, 빌드 전 원본 바이트로 복원했다. SHA-256은 빌드 전후 모두 `45394688702DBA33CA8555111CB91A97D558098B9B49E413F3CD38E4C122BE8B`이다.
- PD 밸런스 파일 SHA-256은 전후 모두 `8DDD711C95A9C42A8D35C7C33C3225D62387EB7AED5F723AF03E7550AF0F5A6C`이다.
- 새 실행 파일의 격리된 balance-editor study에서 146개 검사와 36개 캡처가 실행됐다. 이번 재장전 마이그레이션, 부분 탄창, 빈 탄창, 자동 재장전 검사는 모두 통과했다. 전체 study는 다른 기존 검사 2개(센서 머리 시각 구분, 근접 무장 공격 피해) 실패로 종료 코드 2를 반환했다. (`Logs/Reload-Unification-Editor-Study-20261113.log`)

## 다음 단위

나머지 9개 기본 수치와 특수 동작을 한꺼번에 바꾸지 않는다. 다음 회차에서 실제 소비 지점을 다시 확인한 뒤 무게와 반동 중 작은 변경 하나를 선택하고, 기존 특수 발사·우클릭 동작을 유지하는 검사를 추가한다.

## 2차 반영 — 발사 반동 표시

- 무기별 `recoil` 값을 편집 데이터에서 실전 무기 프로필과 가상 대전 프로필까지 전달한다.
- 성공한 플레이어 사격에 한해 반동 수치(0~100%)를 카메라의 짧은 시각 흔들림으로 연결했다. 최댓값도 화면 이동 0.12 월드 단위로 제한한다.
- 탄도와 조준 방향은 변경하지 않으며, AI 사격과 탄 생성 실패는 플레이어 화면 반동을 만들지 않는다.
- 사용자 밸런스 파일은 변경하지 않았다. 새 기본 데이터에서는 반동 기본값이 0이며 PD가 무기별로 조절할 수 있다.

## 3차 반영 — 무기 무게 편집과 기존 낙하 계산

- `weight`를 총기와 방패의 편집 가능 수치로 노출했다. 이미 있는 전투 프로필의 무게 및 낙하 영향 계산을 사용하며, 새 총 적재 한도나 별도 무게 시스템은 추가하지 않았다.
- 탄약 1발 무게(`ammoWeight`)는 계속 내부/비활성으로 두었다. 무게는 현재 `FallWeightFactor` 계산에 사용되며, 방패 무게는 기존 이동속도 조정에도 반영된다.
- 스모크 검사에 무기 무게 25kg이 기존 낙하 계수를 정확히 0.25 올리는 회귀 검사를 추가했다. 밸런스 편집 검사에도 총기·방패 무게는 편집되고 탄약 무게는 내부 값인지 확인하는 항목을 추가했다.
- PD 밸런스 파일은 수정하지 않았다.
