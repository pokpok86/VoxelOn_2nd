# 시스템 확장 30분 작업 — 4차 설계별 파츠 값과 v4 이전

작성: 2026-11-06. 현재 작업은 work 기준 작업 트리에만 있다. `main`은 변경/병합하지 않았고 커밋·푸시는 하지 않았다.

## 구현

- 저장 형식을 v3에서 v4로 확장했다. 각 8개 설계 슬롯은 이제 18개 파츠 정의의 독립 수치 사본을 보유한다.
- 구형 v1/v2/v3 파일은 기존 기체별 `parts` 수치를 각 슬롯에 복사해 v4로 이전한다. v3의 같은 기체 슬롯들은 이전에 공유하던 값으로 시작하고, 저장 후에는 독립 편집된다. 불러오기는 원본 파일을 덮지 않고, 저장 시 기존 파일의 `.bak` 백업을 만든다.
- v4는 설계 슬롯마다 파츠 목록 수·ID·분류와 수치 범위를 검증한다. 파츠 ID를 빠뜨리거나 NaN을 저장하려 하면 거부한다.
- 파츠 수치 화면에 현재 설계 ID를 표시하고, 편집/메모를 그 슬롯의 파츠 사본에 기록한다. 슬롯 복사·붙여넣기·초기화도 파츠 값까지 함께 다룬다.
- 전투 적용 시 플레이어는 활성 설계의 해당 기체 파츠 값을 사용한다. 다른 프레임의 상대 기체는 종전 공용 기본값을 사용하며, 저장된 무기/파트 옵션을 임의로 전투 규칙으로 추가 연결하지 않았다.

## 실제 검증

- Unity 6000.6.7f1 Windows 빌드 최종 성공: `VOXSKY_BUILD_PASS 237254162 bytes`, `Logs/DesignSlots-Iteration4-Build.log`. 첫 컴파일에서 배열 복사 래퍼 반환 형식과 UI `System.Array` using 두 오류가 발견되어 수정 후 재빌드했다.
- 실제 Windows 플레이어 밸런스 편집 검사 종료 코드 0: `BALANCE_EDITOR_STUDY_PASS 60 checks; 11 images`, `Logs/DesignSlots-Iteration4-EditorStudy.log`. v1/v2/v3 이전, v4의 누락/NaN 거부, 설계 슬롯 복사·초기화, 파일 저장/재로드, 같은 WISP 두 슬롯의 독립 코어 값, 각 선택 설계의 실제 기체 적용을 확인했다. 첫 시험에서는 캡처 뒤 선택 슬롯이 4번에 남아 기존 무기 검사가 실패했다. 검사 준비에서 1번 슬롯 복원을 추가하고 전체 60개를 재실행해 통과했다. 검사 기준은 낮추지 않았다.
- 전투 회귀 종료 코드 0: `VOXSKY_SMOKE_PASS 358 checks`, `Logs/DesignSlots-Iteration4-Smoke.log`.
- 실제 4번 슬롯 파츠 화면: `Docs/Screenshots/Balance-Editor-20261106/SchemaV4-Iteration4/03b-independent-part-tuning.png`. 상단에 DESIGN_04가 표시되고 파츠 편집 화면을 확인했다. 사용자 직접 조작/밸런스 승인은 아직이다.
- 빌드 스크립트가 기본값과 일치하는 `Data/Balance/PD-Balance.json`/템플릿을 v4로 갱신했다. 사전 SHA-256 비교에서 두 파일이 동일했고, 기존 숫자 설정을 바꾸지 않고 슬롯별 기본 파츠 사본을 추가했다. 빌드가 다시 쓴 `Assets/Scenes/Arena.unity` 내부 ID 변경은 작업 트리에서 원복했다.

## 제한과 다음 단계

- 슬롯에는 현재 18개 고정 파츠 ID가 들어간다. 아직 ID만 정의해 새 파츠를 등록하는 확장 레지스트리는 없다.
- 일부 저장 수치(`plannedWeight`, 무기 무게·락온·에너지 등)는 계속 실험/보관용이며, 게임에 영향을 주지 않는다. 적용되는 기존 구현 수치만 실제 기체에 반영된다.
- 다음에는 고정 길이 배열 대신 안정된 ID 정의와 별도 스탯 데이터를 갖는 무기/파츠 카탈로그 구조를 검토하고, 기존 항목 한 개를 새 정의 방식으로 이전한 뒤 회귀 검사를 한다. 새 무기/파츠의 실제 전투 기능은 구현 가능한 작은 수직 항목을 선정해 따로 검증한다.
- Windows 빌드와 자동 검사는 통과했다. 시각적·밸런스 최종 승인은 박PD 직접 플레이가 남아 있다.
