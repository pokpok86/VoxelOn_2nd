## 적용 및 미적용 현황

| 요청 | 현재 구현 | 판정 / 주의 |
|---|---|---|
| 무기 기본 수치를 9개로 정리 | 편집기 기본 수치 선택자는 `damage`, `interval`, `speed`, `radius`, `range`, `capacity`, `reloadTime`, `weight`, `recoil`만 노출한다. | **적용됨.** 실제 노출은 각 항목의 `implemented` 표시에도 좌우된다. 현재 PD 데이터에서 무게와 반동은 적용된 값으로 표시된다. 기획 문서에는 이 둘을 보관용으로 두고 별도 전투 연결 검증이 필요하다고 적혀 있어 상태가 다르다. |
| 분리 재장전 값을 통합하되 호환 유지 | `reloadTime`이 없으면 기존 `partialReload`와 `emptyReload` 중 큰 값을 새 값으로 마이그레이션한다. 기존 키, `idleReload`, `spread`, `blast` 등은 저장 구조 및 전투 프로필에 남아 있다. | **대체로 적용됨.** 내부 필드는 제거하지 않았다. 통합 전 값이 서로 다를 경우 큰 값이 선택되므로, 마이그레이션 결과가 의도한 수치인지 기존 저장본으로 추가 대조할 필요가 있다. |
| 특수 기능·아이콘·우클릭 동작 분리 | 아이콘과 `specialFunctionIds`는 별도 보관한다. `secondaryActionId`는 `NONE`, `LOCK_ON`, `GUARD`만 허용한다. 특수 기능 ID는 편집기에서 “새 효과 미적용”으로 표시한다. | **부분 적용.** 저장·아이콘과 실제 동작은 분리됐다. 무기별 액션 체계는 아직 락온/가드 수준이며, 바주카 포격 자세나 근접 세로 베기 같은 액션은 미구현이다. 특수 기능 ID도 효과로 실행되지 않는다. |
| 머리 기본값: 감지 성능·무게 | `radarRange`, `plannedWeight` 편집. | **부분 적용.** 감지 대표값으로 레이더 범위를 제공한다. `plannedWeight`는 UI에 보이나 `implemented=false`이며 전투에 반영되지 않는다. 락온 범위와 레이더 범위가 별도 내부 키로 유지된다. |
| 몸통 기본값: 내구도·에너지·무게 | `health`, `boostCapacity`, `plannedWeight` 편집. 현재 기체 구성 시 `armor=0`으로 적용한다. | **부분 적용.** 피해 감소는 현재 선택 기체에서 비활성화. 이전 `armor` 값은 데이터 호환을 위해 보존된다. 파츠 무게는 초안 값이며 전투 계산에 미적용이다. |
| 다리 기본값: 이동력·점프력·무게 | `speed`, `jumpHeightScale`, `plannedWeight` 편집. | **부분 적용.** 방향별 속도·점프의 내부 세부 키는 보존된다. `plannedWeight`는 전투에 미적용이다. |
| 백팩 기본값: 부스터·무게 | 부스터 카테고리에서 `boostSpeed`, `plannedWeight` 편집. | **부분 적용.** 부스터 성능 대표값만 기본 편집에 노출된다. 파츠 무게는 전투에 미적용이다. |
| 팔 별도 성능 제거 검토 | 기본 파츠 편집기에는 팔 성능 수치를 노출하지 않고 통합 설명을 제공한다. 기존 팔 조작·안정성 데이터는 내부 보존된다. | **적용됨.** 기존 저장 형식 호환을 위해 값을 삭제하지 않는다. |
| 드론은 백팩 고유 기능, 서브 무기 슬롯 0개 | 현재 특수 기능 ID는 보존 가능하지만 구현되지 않은 효과다. 요청된 백팩별 0/1/2 슬롯 및 드론 전용 슬롯 규칙은 현 상태에서 기능 검증되지 않았다. | **미적용/미검증.** 데이터 필드가 있다는 사실만으로 게임 동작이 구현된 것은 아니다. |
| 수중 진입 시 색조·안개 | `UpdateClimate`에 물 깊이에 따른 안개·배경색·조명 변화가 있고, 비·하늘 표시 전환도 있다. 깊이는 현재 `player.root.position`으로 계산한다. | **코드 존재, 시각 검증 미완료.** 기획은 카메라가 물에 잠긴 상태를 확인하라고 요청한다. 플레이어 루트와 카메라 위치가 달라지는 표면 통과 장면을 실제 캡처해야 한다. 현재 자동 검증 로그에서는 수중 색상 전환을 입증하지 못했다. |

## 저장 데이터 호환 및 출처 확인

현재 작업 복사본의 `Data/Balance/PD-Balance.json`은 기준 브랜치의 형식 5와 다르게 **형식 7**이며, `reloadTime`, `secondaryActionId`, `specialFunctionIds` 같은 항목이 추가되어 있다. 작업 복사본 HEAD `cf7ad13b709d8591c3a4312f291a67d3d81885e0`(2026-11-14, `Add WISP part models and review renders`)의 추적 파일은 형식 5다. 현재 파일은 Git 미커밋 변경 **+1033/-370행**이고 `.bak`과 같은 SHA-256 `0F470499D4E21FB112A7E502EA5175C98777B110A7F8F87D0461A21A5A1201E9`를 가진다. 두 파일의 수정 시각은 각각 2026-11-18 14:46:02 및 14:45:53이다.

현재 Git diff는 변경이 미커밋임을 확인하지만, 로컬 diff만으로 작성자나 저장 경로를 알아낼 수는 없다. `.bak`과 내용이 완전히 같아 별도 이전 버전의 증거도 아니다. 이전 `PD-Stats-Implementation-20261114.md`에는 과거 해시 `8DDD711C...`가 기록되어 있어 현재 상태와 맞지 않는다. 이번 시각의 검토 중에는 파일을 열어 Unity에 저장하지 않았고 수정하지 않았다. 저장 주체·절차는 미확인으로 남긴다. 이후 검증은 프로젝트 내 해당 파일을 열어 저장하지 않는 격리 복사본에서만 진행한다.

마이그레이션 코드는 `reloadTime`이 없으면 구형 분리 재장전 값 중 최댓값으로 새 값을 만든 뒤 기존 항목을 유지한다. 저장 검증은 이미 수행된 편집기 연구에서 155개 검사 통과로 기록되어 있다. 다만 그 검증 결과가 현재 변경된 PD 파일의 출처를 설명하지는 않는다.

## 스모크 20건 실패의 상태

현재 작업 복사본에서 확인 가능한 최신 플레이어 스모크 로그는 `Logs/PD-Stats-Implementation-Smoke-4.log`이며 `VOXSKY_SMOKE_PASS 377 checks`를 기록한다. 11월 18일 시각 후보 연결 후에도 `%TEMP%\voxelon-visual-candidate-smoke-final\Smoke.log`에서 377개 통과가 확인됐다고 앞선 작업 기록에 남아 있다. 편집기 연구 로그는 155개 통과, 실패 0이다.

반면 요청에 언급된 과거 **실패 20건의 원본 로그 또는 테스트별 실패 목록은 현재 작업 복사본에서 찾지 못했다.** 따라서 그것이 기존 실패인지, 새 회귀인지, 변경된 설계에 뒤처진 검사인지는 지금 증거만으로 분류할 수 없다. 현행 스모크가 통과했다는 사실만으로 과거 20건을 소급 분류하지 않는다. 분류에 필요한 자료는 당시 로그와 테스트 이름/실패 메시지다.

## 수정 우선순위 제안

1. **수중 화면 실패를 재현하고 카메라 기준으로 판정 검증**: 수면 위, 카메라만 잠김, 기체와 카메라 모두 잠김, 깊은 수중을 동일 카메라 구도로 캡처한다. 필요하면 플레이어 루트가 아닌 실제 카메라 위치 기준으로 색조/안개 전환을 맞춘다.
2. **요청된 과거 스모크 실패 20건 원본 확보**: 각 실패를 코드 회귀, 기준 설계 변경, 테스트 기대값 노후화로 분류한다. 로그 없이 기존 테스트를 삭제하거나 기대값을 낮추지 않는다.
3. **데이터 현행화는 복사본에서만 검증**: 포맷 5 저장본과 7 저장본을 격리 복사본에서 왕복 저장하고, 기존 내부 전투 필드 및 사용자 PD 데이터가 보존되는지 해시/키 단위로 대조한다. 현재 `PD-Balance.json`의 수정 주체가 불명확하므로 원본을 재저장하지 않는다.
4. **액션/특수 기능은 PD가 합의한 ID와 수치가 준비된 뒤 구현**: 우선 액션 ID의 스키마를 확장할지 설계만 확정하고, 승인 전까지 포격 자세·드론·락온 보조 기능을 임의로 추가하지 않는다.

## 현재 판정

간소화된 편집 UI와 호환 마이그레이션은 구현되어 있고, 기본 회귀 및 편집기 검사는 통과 기록이 있다. 그러나 액션 종류·백팩/드론 슬롯 구조는 일부만 연결되어 있으며 수중 화면은 렌더 캡처 검증이 남았다. 과거 스모크 20건은 원본 실패 자료가 없어 분류 미완료다. 본 검토는 보고서 작성만 수행했으며 코드, PD 밸런스 파일, 씬, Blender 원본, 브랜치 히스토리를 수정하지 않았다.
