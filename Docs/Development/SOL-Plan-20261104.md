## DEV-002 우선 검토

### 현재 확인한 사실

1. CraftCatalog.Selectable에는 네 프레임이 있지만 UnlockedCount=1. 탱크 방향 가속/낮은 점프, TARANTULA 사족·차지 점프/수평 부스터 제한 메타데이터와 절차형 동작 일부가 존재한다. 완성된 플레이 후보로 간주하지 않는다.
2. Assets/Art/Robots/BASTION 및 TARANTULA 폴더는 비어 있다. 해당 Blender/FBX 모델은 없다.
3. ApplyImportedWisp는 이름 WISP만 허용하며 Left_thigh/Right_thigh까지 필수로 요구한다. 탱크·사족은 이를 그대로 사용할 수 없다.
4. 렌더·카메라 헤드 캐시·다리 애니메이션·방패/무기 배치에도 WISP 이름/이족 관절 의존성이 있다. 기체별 모델 정의와 소켓 검증을 분리해야 한다.
5. 실제 플레이 Attack은 weaponSlot!=1이면 발사하지 않는다. Fighter에는 탄창/장전 상태 한 벌만 있다. 보관된 공격 타입/슬롯과 실제 4슬롯 호환성을 혼동하지 않는다.
6. 충돌은 Unity Rigidbody 전환이 아니라 기존 반경/Bounds/지면 높이 방식이다. 이번 작업에서 물리 엔진을 통째로 교체하지 않는다.

### 구현 순서와 완료 게이트

A. WISP v005 원본/관절/아틀라스/현재 실행 빌드를 보존. 모델 정의에 상체·하체 타입·무장 소켓·접지 기준·충돌 발자국을 명시. 이름 대신 모델/리그 능력으로 연결한다.
B. Blender에서 WISP 상체·머리·팔·무장 마운트를 재사용한 BASTION 새 blend/FBX 생성. 이족 하체는 제거하고 실제 두 궤도 루프·차륜·차대를 제작. Unity 프리팹, 궤도 이동 표현, 낮은 지면 기준과 전진/회전 기동 연결. WISP 크기는 변경하지 않는다.
C. 같은 상체 기반 TARANTULA 새 blend/FBX 생성. 좌우 4개의 엉덩이/무릎/발끝 관절, 넓은 지지 구조와 접지 보행 구현. 공중/지상 자세와 지형 높이 대응 검증. 기존 차지 점프와 대시 제한을 먼저 연결해 실제 동작을 확인한다.
D. B/C 각각 모델 도입 후 독립 Windows 빌드 및 해당 기체 스모크/실제 화면 검증. 1·2·3 플레이어/상대 조합, 이동·점프/부스터·사격·피격·접지·벽/모서리·카메라·리스폰 검증. 이상이 없을 때 선택 제한을 3기로 확대. HOUND는 잠금 유지.
E. 4슬롯은 무기 소켓/상태 인터페이스를 준비하되 DEV-002만으로 새 무장 4종을 완료 처리하지 않는다. 슬롯별 탄약·장전·입력 및 실사용 검증은 WEAPON-001과 연결한다. DEV-002의 전체 무장 호환성 완료 여부를 따로 보고한다.
F. 정면/측면/후면/게임뷰와 접지·점프 비교를 Docs/Screenshots의 새 폴더에 저장. 세 기체가 플레이 가능한 후보를 먼저 제출하고 상체 디테일은 이후 보강한다.
