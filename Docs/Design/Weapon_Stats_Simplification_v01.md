# VoxelOn_2nd — 무기 기본 수치 간소화 기획서 v0.1

- 작성: PD / Max 기획 합의
- 상태: **기획 확정(9개 기본 수치)** / 구현 착수 전 기존 데이터 호환성 검토 필요
- 대상: WISP 하박 일체형 무기 설계 및 향후 무기 공통 사양
- 저장 위치: GitHub `main` 기획 문서. **이 문서를 올렸다고 기존 빌드나 밸런스 파일을 즉시 수정하라는 뜻은 아님.**

## 1. 의도
현재 `Docs/Balance/PD-Balance-Template.json`에 무기 수치 항목 20종이 있음. 지나친 세분화는 밸런싱 부담과 구현 버그 위험을 늘리므로 **일반 무기 기본 수치는 9종으로 제한**한다. 단, 무기 자체의 발사 방식·특수 기능·마우스 우클릭 보조 액션은 별도로 표현한다.

## 2. 최종 선정: 기본 수치 9종

| # | 표시 이름 | 기획상 키 | 기존 템플릿 대응 | 의미 |
|---|---|---|---|---|
| 1 | 공격력 | `damage` | `damage` | 한 번의 유효 명중 피해량 |
| 2 | 발사 간격 | `interval` | `interval` | 발사 사이의 간격(초) |
| 3 | 탄속 | `speed` | `speed` | 탄환 이동 속도(m/s) |
| 4 | 탄환 판정 반경 | `radius` | `radius` | 충돌 판정 크기(m), 시각적 모델 크기와 별도 |
| 5 | 사거리 | `range` | `range` | 유효 최대 거리(m) |
| 6 | 탄창 크기 | `capacity` | `capacity` | 장전 탄수 |
| 7 | 재장전 시간 | `reloadTime` (기획 표기) | `partialReload`, `emptyReload` 통합 필요 | 단일 재장전 시간(초) |
| 8 | 무게 | `weight` | `weight` | 파츠 조합의 총중량 및 장착 제한 |
| 9 | 반동 | `recoil` | `recoil` | 발사 시 총구 흔들림/기체 반응 |

**주의:** `reloadTime`은 신규 기획 키 예시이며, 실제 Unity 데이터 키를 지금 변경하지 않는다. `weight`, `recoil`은 원본에서 현재 **보관용(전투 미적용)** 상태다. 구현 시 별도 연결 및 검증이 필요하다.

## 3. 기존 20종에서 간소화되는 항목
- `partialReload` + `emptyReload` → 단일 '재장전 시간'으로 통합. 구버전 파일 호환성을 확인하고 마이그레이션 경로 준비.
- `idleReload` → 기본 무기 설계 항목에서 제외. 현행 자동 장전 로직을 삭제할지, 내부 고정 규칙으로 둘지는 구현 조사 후 결정.
- `spread` → 공통 9종 항목에서 제외하되, **탄퍼짐/산탄 패턴과 조준 보정은 동작상 구분**한다. 샷건 등 개별 무기 고유 발사 방식에서 관리하며 현행 게임 로직을 무턱대고 제거하지 않는다.
- `blast` → 폭발 특수 기능 또는 폭발형 무기의 개별 효과 설정으로 이동; 기존 폭발 판정은 보존.
- `ammoWeight`, `lockPenalty`, `energyPerShot`, `heatPerShot`, `cooling`, `maxHeat` → 기본 수치 목록에서 제외.
- `lockStrength` → 머리/기체의 락온 관련 옵션 및 무기 락온 지원 여부 설계로 분리.
- **제외란 곧바로 코드를 삭제하라는 지시가 아니다.** 현행 세이브/밸런스/전투 동작과의 호환성 검토 후 필요한 최소 변경만 제안한다.

## 4. 수치 외 필수 구분(별도 구조)
1. **무기 고유 특성:** 단발·연사·버스트·산탄·근접 판정 등. 예: 연사 강화와 버스트는 특수 스킬이 아니라 무기 본래의 발사 방식.
2. **특수 기능:** 관통, 폭발, 유도, 락온 기능 등 승인된 기능 ID와 관련 파라미터를 연결. 전부를 각 무기의 기본 수치 필드로 만들지 말 것.
3. **조작 액션:** `primaryAction`(좌클릭), `secondaryAction`(우클릭) 및 `lockOnSupported`. 우클릭은 무기에 따라 락온, 포격 자세, 세로 베기, 하박 가드 등 다르게 동작.
4. **장착 조건:** WISP는 손으로 쥐지 않는 하박 일체형 무기. 좌/우 하박 연결 규격을 준수. 무게 초과 및 백팩 유형 제약은 별도 장착 시스템으로 관리.
5. **조준 보정:** 무기의 기본 조준 보정은 무기 고유 특성이고, `조준 보정 강화`는 머리 등 파츠에서 제공할 수 있는 특수 옵션.

### 무기별 예시 (수치 미확정)
- **W-01 LUMEN 레이저:** 원거리 무기, 락온 지원 후보. 우클릭 락온.
- **W-02 BREAKER 바주카:** 락온 없음(PD 결정). 우클릭으로 **포격 자세**, 이때 조준 정확도 상승·반동 감소, 이동 제약. 구체 배율은 테스트 후 승인.
- **W-04 EDGE 블레이드:** 하박 일체형 근접 무기. 우클릭 세로 베기 또는 가드 후보.
- **W-05 AEGIS 하박 방패:** 디자인 보류. 몸통의 `실드` 특수 기능과 일반 하박 가드는 구분.

## 5. 특수 기능 범주 v0.4 참고 (23개, 확정/검토 후보 혼재)
- 공격(8): 차지 샷, 관통, 확산, 유도, 폭발, 지속 피해, 드레인, 락온 기능
- 방어(1): 실드
- 기동(5): 부스터 강화, 점프, 체공, 낙하 완충, 고속 이동
- 지원(3): 락온 향상, 락온 안정화, 조준 보정 강화
- 전자전(3): 재밍, 유도 방해, 락온 교란
- 드론(3): 공격 드론, 요격 드론, 교란 드론. 이 셋은 **서브웨폰이 아닌 백팩 자체 기능**, 해당 백팩은 서브웨폰 슬롯 0개.

## 6. 길이에게 요청하는 기술 검토 (문서 우선, 작업 실행 아님)
- 기존 `Docs/Balance/PD-Balance-Template.json`의 20개 수치와 실제 Unity 무기 데이터 소비 지점 대응표 조사.
- 단일 재장전 시간 전환 시 구형 JSON 및 게임 저장 파일 호환 전략.
- 공통 9종을 제외한 필드 중 실제 공격 판정/조작에 필요한 내부 파라미터 식별.
- 아직 보관용인 무게와 반동을 구현할 최소 범위 및 테스트 방법 제안.
- 우클릭/락온/포격 자세가 기존 입력과 충돌하지 않는지 확인.
- 개발 작업에 들어가기 전 변경 계획 및 예상 영향 범위를 PD에게 보고. **기존 데이터 파일 삭제·대량 이름 변경·런타임 일괄 교체 금지.**
