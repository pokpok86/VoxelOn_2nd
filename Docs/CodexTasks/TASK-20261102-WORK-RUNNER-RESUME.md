# VoxelOn work 브랜치 운영 및 자동 러너 재개 지시

## 현재 기준
- 저장소: pokpok86/VoxelOn_2nd
- 안정 브랜치: main
- 개발 브랜치: work
- 공통 기준 커밋: b757bcca068acbf59cd0eed4f97910246202f2bb
- 해당 커밋의 Windows 빌드 성공 및 스모크 검사 209개 통과는 기존 개발자 보고에 근거함. 이번 지시서 작성 과정에서 재검증하지 않음.

## 재개 전 확인
1. Windows 러너가 실제 중지 상태인지, 이전 작업이 완료되었는지 확인한다.
2. 로컬 미커밋 변경사항과 미푸시 커밋이 있으면 보존하고 보고한다. 절대 강제 초기화하지 않는다.
3. 원격 work를 fetch하여 기준 커밋 및 최신 HEAD를 확인한다.
4. 작업 브랜치를 work로 설정하고 원격 work를 추적한다. 충돌 또는 예상 밖의 변경이 있으면 중단하고 보고한다.
5. GitHub 인증, Codex 실행 승인, Unity 배치 빌드 권한을 점검한다. 추가 승인이 필요하면 사용자에게 요청하며 우회하지 않는다.

## 운영 규칙
- 일상 개발은 work에 커밋/푸시한다.
- main은 별도 승인 없이 수정하거나 병합하지 않는다.
- 새 브랜치는 매니저가 생성 및 지정한다.
- 개발 변경 후 CM이 Unity 빌드와 테스트를 실행하고 성공/실패 및 로그를 기록한다.
- 작업 중복 실행을 막는 잠금/작업 ID를 사용한다.
- 오류 자동 복구는 제한된 재시도만 수행하고 실패 시 보고한다.
- 텔레그램 연결 정보가 없으면 전송 성공을 주장하지 않는다. 토큰은 저장소에 커밋하지 않는다.

## 러너 재개
이 문서의 등록만으로 러너를 시작하지 않는다. 사용자가 원격 PC 개발자에게 명시적으로 재개를 지시하면 위 사전 점검 후 스케줄을 활성화한다.
